--- ISSUE 1: n_bins = 1 features selected with non-zero IV ---
Observation: EMERGENCYSTATE_MODE (IV 0.023) and HOUSETYPE_MODE
(IV 0.021) were SELECTED despite showing n_bins = 1, apparently
contradicting the SCOFR/bad-debt flags which showed n_bins = 1
with IV = 0.000.

Bin table for EMERGENCYSTATE_MODE:
  Bin            Count    Count%   Event rate   WoE       IV
  (-inf, inf)   161,756   52.60%     7.00%     +0.1538   0.0117
  Special             0    0.00%     0.00%      0.0000   0.0000
  Missing       145,755   47.40%     9.26%     -0.1503   0.0114
  Totals        307,511  100.00%     8.07%              0.0231

RESOLUTION: not a bug — a counting convention.
The n_bins column counts NUMERIC SPLIT INTERVALS only. All
non-missing values fell into a single interval, hence n_bins = 1.
The Missing bin is not counted even though it holds 47.4% of the
population and contributes half the IV.

The feature is genuinely splitting on PRESENT vs MISSING, and
that split is informative (7.00% vs 9.26% event rate).

Correct reading of the summary table:
  n_bins = 1 AND IV ≈ 0     → genuinely one bin, no signal
                              (SCOFR, bad debt, microloan,
                               mortgage, BB_FLAG_EVER_DPD_120)
  n_bins = 1 AND IV > 0     → split is missing-vs-present,
                              i.e. informative missingness
                              (EMERGENCYSTATE_MODE, HOUSETYPE_MODE)

This VALIDATES the Phase 4 bucket-3 decision. Leaving building
stats as NaN rather than imputing them allowed the WoE binner to
extract signal from the missingness itself. EMERGENCYSTATE_MODE's
entire predictive value is "do we hold building data for this
applicant" — a proxy for apartment-block dwelling.

--- ISSUE 2: DEBT_TO_INCOME / CREDIT_TO_INCOME screened out ---
Both were EDA-mandated domain ratios; both fell below the IV 0.02
gate (0.0067 and 0.0040). Question: did the monotonic constraint
force a poor split?

Bin table for DEBT_TO_INCOME:
  Bin              Count   Count%   Event rate    WoE       IV
  (-inf, 0.06)    16,715    5.44%     6.66%    +0.2069   0.0021
  [0.06, 0.10)    45,934   14.94%     7.35%    +0.1023   0.0015
  [0.10, 0.16)    82,746   26.91%     7.75%    +0.0438   0.0005
  [0.16, 0.20)    52,319   17.01%     8.44%    -0.0488   0.0004
  [0.20, inf)    109,797   35.71%     8.66%    -0.0761   0.0021
  Totals         307,511  100.00%     8.07%              0.0067

RESOLUTION: the binning is textbook-correct.
  - Five bins, all well populated (5.4% to 35.7%)
  - Perfectly monotonic: event rate rises 6.66% → 8.66%,
    WoE descends +0.207 → -0.076 without reversal
  - No missing, no special values

The monotonic constraint did NOT force a bad split. The effect
size is simply small: only ~2 percentage points of default-rate
separation from lowest to highest DTI bin.

INTERPRETATION — RANGE RESTRICTION:
Home Credit already screens on affordability at application.
Applicants with dangerously high debt-to-income were declined
before entering this dataset. The surviving population therefore
has DTI compressed into an acceptable band, and residual
variation within that band predicts little.

This is a well-known phenomenon in credit scoring: on an
approved-applicants-only sample, the variables the lender
screens on show artificially weakened relationships. The
feature is weak BECAUSE OF HOW THE DATA WAS GENERATED, not
because affordability is irrelevant to credit risk.

DECISION: accept the exclusion for the scorecard track. The
feature remains available in the challenger track, where
LightGBM can use it in interactions (it ranks 26th by gain —
see section 4).

2. CLUSTER REPRESENTATIVE SELECTION
================================================================

--- SELECTION RULE: IV-FIRST, RS_RATIO AS TIEBREAKER ---
Within each cluster, retain the variable with the highest
Information Value; break ties on lowest RS_Ratio.

RATIONALE:
RS_Ratio = (1 - RS_Own) / (1 - RS_NC) measures how well a
variable represents its cluster STRUCTURALLY. It is a purely
geometric criterion with no knowledge of the target.

IV measures PREDICTIVE POWER against the target.

For a scorecard, the objective is to predict default, not to
summarise variance. The cluster member that best predicts the
outcome is the correct choice; structural representativeness
is secondary.

--- DISAGREEMENT ANALYSIS ---
IV-first and RS_Ratio-first disagreed in 20 of 25 clusters.
Three patterns emerged:

PATTERN A — trivial disagreements (~6 clusters)
Near-identical variables where the choice is arbitrary:
  Cluster  0: FLOORSMAX_MEDI (RS .268, IV .0381) vs
              FLOORSMAX_AVG  (RS .275, IV .0384)
  Cluster  8: ENTRANCES_MEDI vs ENTRANCES_AVG
  Cluster 14: EXT_1_2_3_STD vs EXT_2_3_STD
  Cluster 18: YEARS_BEGINEXPLUATATION_AVG vs _MEDI
  Cluster 22: NONLIVINGAREA_MEDI vs NONLIVINGAREA_AVG
Same construct measured two ways. Either choice is defensible.

PATTERN B — IV-first clearly superior (~13 clusters)
Substantially stronger predictor at modest structural cost:
  Cluster 21: CODE_GENDER (IV .039) → EXT_SOURCE_1 (IV .146)  3.8x
  Cluster  6: FLAG_EMPLOYED_SENTINEL (.033) → YEARS_BIRTH (.086) 2.6x
  Cluster 11: MEAN_AMT_CREDIT_SUM_DEBT (.052)
                              → DEBT_TO_CREDIT_RATIO (.103)   2.0x
  Cluster  7: COUNT_BUREAU_CLOSED (.041)
                              → DAYS_SINCE_FIRST_CREDIT (.078) 1.9x
  Cluster 20: NAME_EDUCATION_TYPE (.050) → OCCUPATION_TYPE (.080)
  Cluster 12: CC_MEAN_AMT_BALANCE (.044) → CC_MEAN_UTILISATION (.061)
  Cluster  5: COUNT_PREV_REFUSED (.055) → REFUSAL_RATE (.070)
This validates the IV-first rule.

PATTERN C — IV-first FAILURE (1 cluster) → guard added
  Cluster 1: IV-first selected CREDIT_TO_GOODS
             (RS_Own 0.010, RS_Ratio 1.010, IV 0.076)
             over FLAG_HAD_DRAWING (RS_Ratio 0.180, IV 0.025)

An RS_Ratio ABOVE 1 means the variable is better explained by
a DIFFERENT cluster than its own. CREDIT_TO_GOODS does not
belong to cluster 1 — it was parked there by default. Selecting
it would have left cluster 1's actual content (credit card
behaviour) entirely unrepresented.

--- GUARD IMPLEMENTED ---
Variables with RS_Ratio >= 1.0 are disqualified as cluster
representatives, but RETAINED SEPARATELY as "orphans".

Reasoning: a variable with RS_Ratio >= 1 represents nothing —
but that also means its information is NOT captured by any
cluster representative. Dropping it would lose signal.
Retaining it separately is the correct treatment.

Orphans identified:
  Variable            RS_Own    RS_Ratio    IV
  CREDIT_TO_GOODS     0.0105    1.0101    0.0761
  ANNUITY_TO_CREDIT   0.0035    1.0421    0.0290

After the guard, cluster 1 is correctly represented by
CC_FLAG_EVER_OVER_LIMIT (genuine credit-card behaviour).

--- OUTPUT ---
  25 cluster representatives
+  2 orphan variables
= 27 features after VARCLUS

3. STEPWISE VIF
================================================================
Threshold: 5.0 (strict)
Method   : iteratively drop the highest-VIF feature until all
           remain below threshold
Input    : 27 features from VARCLUS

RESULT: 0 features dropped. All 27 retained.

--- WHY THRESHOLD 5 RATHER THAN 10 ---
For a regulatory scorecard, coefficient stability and
interpretability outweigh marginal predictive gain. VIF 5
corresponds to R² ≈ 0.80 against the other predictors; beyond
that, standard errors are inflated enough that coefficient sign
and magnitude become unreliable — which undermines the entire
purpose of a scorecard that must be explained and defended.

Maximum VIF is 2.27 — less than half the strict threshold.
Most features sit near 1.0, i.e. essentially independent.

--- INTERPRETATION ---
That VIF dropped nothing is the EXPECTED outcome, not a failure
of the check. VARCLUS clusters on correlation structure and
retains one representative per cluster, so the survivors are by
construction weakly correlated. VIF then finds nothing left to
remove.

The two methods are complementary but overlapping: VARCLUS
handles STRUCTURAL redundancy (variables measuring the same
construct); VIF catches LINEAR redundancy surviving clustering
(a variable explained by a combination of several others). Here
VARCLUS did the work and VIF confirmed the result is clean.

Residual mild correlation is visible in the top values — the
building-stat group (2.27, 2.24, 2.11, 1.94) and the EXT_SOURCE
pair (2.10, 2.08). VARCLUS split these into separate clusters
but they still share some underlying signal. Not problematic at
these levels.

--- DEBUGGING NOTE: EARLY STOPPING ON THE WRONG METRIC ---
The first two attempts produced a broken model (only 17 features
with non-zero gain, AUC 0.72). Root cause:

  [100]  valid_0's auc: 0.778186   binary_logloss: 0.546456
  Early stopping, best iteration is:
  [1]    valid_0's auc: 0.720858   binary_logloss: 0.27582

Early stopping monitored BOTH auc and binary_logloss and
defaulted to the first metric tracked — logloss. Logloss was
0.276 at iteration 1 and rose to 0.546 by iteration 100, so by
that criterion iteration 1 genuinely was "best". The model
stopped after a SINGLE TREE, which explains why only 17 features
had non-zero gain: one tree can only make ~31 splits.

The logloss degradation is caused by is_unbalance=True, which
reweights classes and destroys probability calibration — raw
probabilities drift from the observed base rate, inflating
logloss even as ranking (AUC) improves.

FIX: metric="auc" plus first_metric_only=True on both the
estimator and the early-stopping callback.

CARRY-FORWARD TO PHASE 6: is_unbalance improves ranking but
wrecks calibration. Credit risk requires calibrated PDs, not
merely correct rankings. The production model should train
WITHOUT is_unbalance and handle imbalance at the decision
threshold, or apply post-hoc calibration.

Three distinct causes, none of which invalidate the scorecard:

(a) HIGH-CARDINALITY BIAS — ORGANIZATION_TYPE
    Rank 2 by gain (220,927) but IV only 0.071. With 58
    categories, a tree has enormous splitting opportunity,
    which inflates gain. WoE binning compresses it to ~6 bins,
    and IV reflects only that coarse separation. Gain importance
    is a known biased estimator favouring high-cardinality
    features. Not a scorecard failure — a property of the metric.

(b) NON-MONOTONIC AND INTERACTION EFFECTS
    ANNUITY_TO_CREDIT (rank 4, IV 0.029), DEBT_TO_INCOME
    (rank 26, IV 0.007), INST_COUNT_TOTAL (rank 25, IV 0.003).
    Trees exploit non-monotonic relationships and interactions
    that monotonic WoE binning cannot represent by construction.
    This is precisely the capability the challenger track exists
    to provide.

    DEBT_TO_INCOME is notable: it confirms the section-0
    range-restriction finding from the opposite direction. The
    linear/monotonic signal is weak (IV 0.007), yet the tree
    finds usable structure in interactions (rank 26 of 247).

(c) ALREADY-CAPTURED REDUNDANCY — EXT_SOURCE composites
    EXT_1_2_3_MEAN (rank 1) and EXT_2_3_MEAN (rank 3) are the
    two features excluded by the Phase 4 IV > 0.5 gate.
    LightGBM confirms they are the strongest single predictors
    in the dataset.

    This does NOT reverse the Phase 4 decision. Their
    information is already in the scorecard via EXT_1_2_3_MIN,
    EXT_1_3_MEAN and EXT_SOURCE_1 — which is exactly why
    VARCLUS grouped them into the same clusters. The Phase 4
    revisit condition ("reopen if VARCLUS selects a materially
    weaker representative") is NOT triggered: EXT_1_3_MEAN
    (IV 0.414, gain rank 5) and EXT_1_2_3_MIN (IV 0.464, gain
    rank 9) are strong representatives on both criteria.

--- CONCLUSION ---
The two tracks behave exactly as designed. The scorecard
captures stable, monotonic, interpretable signal. The challenger
captures additional non-monotonic, interaction-driven and
high-cardinality signal that a regulatory scorecard cannot
safely use.

Benchmark established: challenger AUC 0.787 on 247 features.
The scorecard logistic regression in Phase 6 will be measured
against this.

================================================================
5. PCA — DOCUMENTED EXCLUSION
================================================================
DECISION: PCA is NOT applied to either track.

--- SCORECARD TRACK: EXCLUDED ON INTERPRETABILITY GROUNDS ---
Principal components are linear combinations of WoE-transformed
features with no business meaning. A scorecard must be able to
state "applicant scored -15 points for high credit utilisation",
not "-15 points for component 3".

PCA is fundamentally incompatible with the interpretability and
regulatory-explainability requirements that justify building a
scorecard in the first place. Adverse-action reasoning, model
validation and regulatory review all require attribution to
original, named features.

--- CHALLENGER TRACK: UNNECESSARY ---
1. Gradient boosting is invariant to monotonic feature
   transformations and handles correlated features natively
   through split selection. PCA offers no benefit.
2. PCA would destroy LightGBM's native categorical handling.
3. PCA would prevent SHAP explanations at the original-feature
   level, which Phase 8 requires.
4. Validation AUC of 0.787 on 247 raw features demonstrates no
   dimensionality problem requiring reduction.

8. OPEN ITEMS FOR PHASE 6
================================================================
1. CV-FOLD REFITTING (carried from Phase 2 leakage scan and
   Phase 4). Binning, WoE, medians and winsorisation caps in
   this project were fitted on the FULL training set. That is
   correct for SCREENING. For MODEL TRAINING, all target-aware
   preprocessing must be refitted INSIDE each CV fold.

   Note that VARCLUS and VIF are NOT target-aware and do not
   require refolding. However, the IV-based representative
   selection IS target-aware — strictly, the whole selection
   pipeline should be re-run per fold to obtain an unbiased
   performance estimate. Document this limitation if a simpler
   approach is taken.

2. CALIBRATION. is_unbalance=True materially degrades logloss
   (0.276 → 0.546). Credit risk requires calibrated PDs, not
   just rankings. Train without class reweighting and manage
   imbalance at the decision threshold, or apply Platt scaling
   / isotonic regression post-hoc.

3. CC_FLAG_EVER_OVER_LIMIT vs CC_MEAN_UTILISATION. Zero
   LightGBM gain for the flag suggests full redundancy with the
   continuous measure. Watch for an unstable or
   counter-intuitive coefficient on either in the logistic
   regression; drop the flag if observed.

4. CHALLENGER BENCHMARK: AUC 0.7869 (LightGBM, 247 features,
   530 iterations, untuned). The scorecard's performance gap
   against this figure is the key result of Phase 7.
